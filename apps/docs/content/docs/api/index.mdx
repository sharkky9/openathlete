OpenAthlete provides a RESTful API for programmatic access to your data.

## Interactive API Documentation

Interactive Swagger UI is served at `/docs` on non-production instances only —
run the API locally (or point at a staging deployment) to explore all endpoints,
try requests, and view schemas:

```
http://localhost:3000/docs
```

## Base URL

```
https://api.openathlete.org
```

For self-hosted instances, use your own API URL.

## Authentication

All API requests require authentication using JWT tokens.

### Getting an Access Token

1. Make a POST request to `/auth/login`:

```bash
curl -X POST https://api.openathlete.org/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "your-password"
  }'
```

2. The response includes an `access_token`:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

3. Include the token in subsequent requests:

```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  https://api.openathlete.org/user/me
```

## Rate Limiting

The unauthenticated endpoints are rate-limited per client IP address, over a
rolling 60-second window:

| Endpoint                     | Limit          |
| ---------------------------- | -------------- |
| `POST /auth/login`           | 10 per minute  |
| `POST /auth/firebase`        | 10 per minute  |
| `POST /auth/refresh-token`   | 20 per minute  |
| `GET /auth/invitation`       | 10 per minute  |
| `GET /auth/email-exists`     | 5 per minute   |
| `POST /user`                 | 5 per minute   |
| `POST /user/password-reset`  | 5 per minute   |
| `POST /user/password-reset/request` | 5 per minute |

Exceeding a limit returns `429 Too Many Requests`. Authenticated endpoints are
not currently throttled.

Throttled endpoints include rate limit headers in their responses:

- `X-RateLimit-Limit` - Request limit for the window
- `X-RateLimit-Remaining` - Remaining requests in the window
- `X-RateLimit-Reset` - Seconds until the window resets
- `Retry-After` - Seconds to wait, sent only on a `429` response

## Error Handling

Errors are returned in a consistent format:

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "error": "Bad Request"
}
```

### Status Codes

- `200` - Success
- `201` - Created
- `400` - Bad Request
- `401` - Unauthorized
- `403` - Forbidden
- `404` - Not Found
- `410` - Gone (endpoint permanently removed)
- `429` - Too Many Requests (rate limit exceeded)
- `500` - Internal Server Error
